## Day 1→2 夜战复盘（四步法）

### 1. 回顾目标

### 2. 评估结果
超预期：门禁体系首轮实战即抓到"虚指待办"（说了没做）——流程价值当场兑现；基线认知两次升版（protobuf-WS 拓扑、18+ 引擎面）。
差距：SFTP 尚无任何产出（P0 三缺一）；全部前端/插件成果停在"待重启验证"，用户可见度为零（明天必须闭环）。

### 3. 分析原因（三次自伤的 5-Why）
- **pkill 自杀**：根因=惯性使用交互式 shell 的模糊匹配而未考虑模式自匹配 → 防线=探测类命令一律 `[x]pattern` 括号技巧。
- **edit 吃标题 ×2**：根因=替换锚点选在结构标题上且 new_string 忘记回补 → 防线=锚点选内容行，或替换后立即 grep 校验标题存在。
- **ESM TDZ**：根因=在无 node 环境下写 JS 无法即时验证 → 防线=关键模块写完做"声明序静态检查"（grep 声明行号 vs 使用行号）。
- 共性根因：**凌晨疲劳期 + 无运行时验证手段**的叠加——行动项：高险代码尽量放在夜间前段；无验证环境时降级为"静态自检清单"。

### 4. 沉淀规律（SOP 化）
- **探针合并律**：每次重启/挂载类验证成本高昂时，把多个探针合并进一个版本，一发验多步（本夜 E5b/c/d 三合一省了两次重启循环）。
- **失败信息榨取律**：安装器的拒绝报文直接白纸黑字列出支持格式——把每次失败输出当 API 文档读。
- **同构位对齐律**：功能优先落在与对标同构的层（历史存储做在前端 IndexedDB 而非引擎侧），换栈零弃件。
