## 二、四维口径逐项判定

### ① 重排逻辑是否被 E2' 证据支撑 —— **方向成立**

- **Go 降级有直接证据**：E2' 是工具链实体上机的内核级拒绝（execve EACCES），法医三连控制了三个混淆变量（动态/静态、SELinux 标签、xattr 保不保留）；V2 又独立佐证了 busybox 先例的真实来源（DSHM 沙箱 files/bin 内）。就决策而言（第三方未签名 ELF 不可执）证据已足够；机制定案（OH 代码签名/hmmac）留给 docs/03 #6，处置正确。
- **A' 升主候选是排除法结论，非直接验证**：B 判死（E1+事实10）、C 判死（V5 硬依赖 cryptography，与 B 同源——但 ADR 尚未如此写，见阻塞-2）、D 否决（安全红线）、Go 被 E2' 杀 ⇒ Phase 1 内唯一具备完整 SSH 语义的可用栈 = 宿主 node + ssh2。排除链在补上 C 的证据后闭合，方向认可。
- **限定**：「升为 Phase 1 主候选」是候选身份重排，不等于可行性确认——A' 前提中仍有未验证项（见②），转正门槛在 E5 系列。

### ② A' 前提假设清单的诚实性 —— 大体诚实，缺一条核心前提

### ③ R2 冲突处置（最大蓝军攻击点）—— 现处置不足（阻塞-3）

现状仅一句「代价=绑定 DSH 生态（原 R2 披露照旧）」，不足之处四点：

1. **无证据基变化声明**：ADR-0002（已接受）矩阵以「演进性 ✕ 绑死 DSH 生态」否决 R2；E2' 证伪了该矩阵所依赖的"execve 随包 ELF 可行"假设后，两份 ADR 现在读起来互相矛盾，必须写明「证据基已变，R2 的引擎形态据此**有条件复权**」。
2. **未接管 0002 的既有条款**：0002 Phase 2 候选 b 明写「若 ADR-0003 落子 Go 则此项与 Phase 1 引擎同体，当前最优先」——重排后该前提失效，不显式取代即成第二条悬空引用（本评审系列对虚指零容忍的既有口径，见 round-2 残余-1）。
3. **弃件成本未披露**：ssh2 JS 栈不在 Phase 2 三候选 a/b/c 任何一路中 ⇒ Phase 1 的 SSH 栈投入对 Phase 2 是弃件（除非新增候选 d：node 随 znCRT HAP——事实 7 双面结论已预警其量级=别人整个工程）。原方案 Go 的「同体」协同被打破，此代价必须写进 A' 成本列。
4. **缺呈报留痕**：产品独立性 vs 当下唯一可行的权衡属产品定位级重大选型，按 arch-design 纪律应呈 Damon 拍板记录在案，不能以一句括号带过。

**为何仍不否决 A'**：0002 自己披露过「R2 与 C 的真实差距当前只有五十步」（Phase 1 独立性本就名义化，引擎实测挂在 DSHM 进程树下）；E2' 之后「当下唯一可行」是有内核级证据背书的事实；R2 否决的是路线级押注，A' 是组件级借用且退出判据（Phase 2 Go 复活）可在场。冲突可处置，但必须落成文字。

### ④ Go 降级的条件表述 —— 方向严谨，两处缺漏

- 已写对的部分：「仅当打进已签名 HAP 随包分发」是**必要条件**表述（勿改成充分——"打进 HAP ⇒ 可跑"未证）；依赖攻关链（HAP 构建/签名通道先通=docs/03 #1）与合流点（Phase 2 引擎存续候选 b）均指明。
- 缺漏 1（并入阻塞-3）：未写明**该条件本身也未验证**——随包 ELF 是否获得执行权取决于 #6 考古（DSHM files/bin 是先例，但 znCRT 自建 HAP 的签名通道是另一回事）；应补出局判据：若 #6 证伪，候选 b 死，Phase 2 引擎存续只剩 a/c，Go 永久出局。
- 缺漏 2：条件应**双向**——若 #6 考古发现第三方 ELF 执行通道（白名单/开发者签名等），Go 可回 Phase 1；现在的表述是单向判死。

### [阻塞-1] 文档自相矛盾：E2' 前旧文未随重排同步改写 + E4 编号撞号

### [阻塞-2] B/C/D 行「维持判死/否决」失真：C 的复活触发条件已满足却未重新裁决

- **位置**：§E2' 后候选重排 表第 3 行「B/C/D｜维持判死/否决」。
- **依据**：历史口径中 C（asyncssh）为「△ 存疑」而非判死，其备选条件明写「**仅当 A 阻塞**」——A 现已降级（阻塞触发），按文档自身逻辑 C 应被重新审视，却被笼统并入「维持判死」。且 C 的旧依据「对 cryptography 依赖版本相关」已过时：V5 实测 asyncssh 2.24.1 requires_dist 首条即 `cryptography>=48.0.1` **硬依赖**，与 B 同源（C/Rust 扩展 × musl-LDSO 拒载 × 本机无工具链，事实 10 + E1）。

### [阻塞-3] R2 冲突处置不足 + 弃件成本未披露 + 0002 候选 b 条款未接管

- **位置**：§E2' 后候选重排 表 A' 行存活条件列（仅一句括号）。
- **依据与改法**：见 §二③ 四点。可执行落法：新增「与 ADR-0002 的关系」小节，含 ①证据基变化声明（E2' 证伪 execve 假设 ⇒ R2 引擎形态有条件复权）；②显式取代 0002 Phase 2 候选 b 的「同体/最优先」条款；③A' 成本列补弃件成本（ssh2 栈不入 a/b/c 三候选，Phase 1 SSH 栈对 Phase 2 为弃件；如欲保留需新增候选 d 并直面试点 7 量级预警）；④Go 双向判据（回 Phase 1 条件 / Phase 2 出局条件）；⑤「本重排呈 Damon 拍板」的留痕行。

### [阻塞-4] A' 存活条件缺「插件长驻 HTTP/WS 服务能力」这一未验证核心前提

- **位置**：§E2' 后候选重排 表 A' 行存活条件列；§验证计划。
- **依据**：A' 的工程形态=插件在宿主 node 内起 SSH 引擎并向前端（浏览器 xterm.js）提供 HTTP/WS 服务——「插件能否开端口并长驻服务」目前零证据（V7/V8 均非插件先例；E4 只覆盖安装面）。前提清单漏列此项，使「升为主候选」的可信度被高估。插件激活语义、HMR 重载对监听器的影响、宿主对插件网络能力的约束均属未知。
- **可执行改法**：①A' 行补列该前提并标注「未验证」；②验证计划列 E5 探针系列，全部带时间盒与失败处置：E5a hello 插件装+挂载冒烟（含重启 DSHM 挂载路径）→ E5b 插件内开 127.0.0.1 端口、HTTP 200 → E5c ssh2 经插件安装队列实装+加载（确认 optional 原生件被跳过、递归深度不触界）→ E5d SSH 连 193:22013 冒烟（口径同 engine/smoke_ssh.py）→ E5e WS 终端回显 + xterm.js 挂接 → E5f SFTP dd 100MB ≥5MB/s + 回显 P95≤80ms + ≥4 并发不劣化。任一步死 ⇒ A' 降回候选池并在 ADR 如实写「Phase 1 无可用 SSH 栈，P0 主链路顺延 Phase 2」，不得静默换目标。**E5 全绿是 A' 转正的门槛。**

### [建议-1] E2' 措辞超出已记录证据半步

「与路径/标签/链接方式无关」中，路径无关性未见图证（busybox 副本是否在不同目录执行未记录）；机制定性「疑 OH 代码签名/hmmac」目前是推断。建议：补记副本实验的绝对路径，或弱化为「与标签/静态与否无关（路径未单测）」；机制保持"假设"字样直到 #6 定案。V2（busybox 在 DSHM files/bin）可补入证据列为推断佐证。

### [建议-2] ssh2 工程细节入验证清单

①node v24.13.0 × ssh2 1.17.0 兼容冒烟（engines 声明 ≥10.16，实测为准）；②optional 原生件（nan/cpu-features）确认跳过且不因安装器递归逻辑报错；③docs/NOTICE.md 记录 license 时以仓库为准（GitHub API 实测 MIT；npm manifest 无 license 字段，勿引错源）；ws 8.22.0 零依赖 MIT。

### [建议-3] A' 运维代价同步重排表与 ADR-0002 生命周期表

### [建议-4] 性能预算带入 A' 验证

ADR-0002 三条性能线（SFTP ≥5MB/s、回显 P95≤80ms、并发 ≥4 路）对 JS 栈不豁免，纳入 E5f 实测口径。

### [建议-5] 转正口径写明

状态行仍是「草案（证据采集中）」。销项+E5 全绿后转「已接受」的条件与时点在文首写明，与 0002 同纪律。

1. **E2' 法医三连方法学过硬**：动态/静态对照、SELinux 标签控制、纯内容复制（不保 xattr）控制变量，三连后收敛到内容级校验——评审人独立复核 busybox 来源（V2）佐证其推断；单条证据推翻自家前案（原 A 主候选），纠错不护短。

## 四、蓝军自检：要推翻这次重排，最硬的一击

> **"A' 是唯一候选"依赖一个未审视的前提——"Phase 1 必须现在就有 SSH"。**
>
> 替代路线存在：Phase 1 先交付非 SSH 的 P0/P1 项（DB 管理、连接历史、UI 骨架——V8 显示四能力全 false，这些本就是欠账），SSH/SFTP/终端顺延到 Phase 2 签名 HAP 通道打通后以 Go 引擎一次到位——保全产品独立性，不绑 DSH 生态，不产生 ssh2 弃件。若 Damon 对 znCRT 的定位是"独立开源应用"，绑定 DSH 的长期能力成本可能高于晚数周交付 SSH 的进度成本；ADR 用"唯一可行"掩盖了"唯一且最贵"的定价问题。
>
> **为何仍不推翻**：章程硬验收以 P0 全绿+本机部署为口径，而 P0 主链路三项（SSH/SFTP/终端）就是全部核心（V8）；无 SSH 的 Phase 1 对验收 #1/#2 贡献趋近于零，项目空转风险大于绑定成本；且 0002 已如实披露 Phase 1 独立性本就名义化（五十步论），A' 加深的是既有耦合而非新增类别，退出判据（Phase 2 Go）在场。但此权衡属产品定位级，**必须呈 Damon 拍板留痕**（已并入阻塞-3 改法⑤）。
